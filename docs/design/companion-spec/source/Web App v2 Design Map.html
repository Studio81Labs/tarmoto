02 · Color · Domain

Road quality scale.

Five-stop ordinal scale, used for road segments, ride scores, day quality, and any product surface that asks "how good is this?". Three palettes exist; switch via the palette tweak. Default is traffic. The scale is always 1→5 left to right: low/bad → high/good.
Traffic · default
Q1Q2Q3Q4Q5

Red → green ordinal. Maximum semantic punch. Use on map polylines, hazards, summary scores.

Muted · paper
Q1Q2Q3Q4Q5

Earth-toned. Use when too many quality bars on screen would oversaturate (route lists, history grids).

Mono · grayscale
Q1Q2Q3Q4Q5

Accessibility & print. Quality encoded by ordering only — pair with bar count, never alone.

--q5 Hero — Tarmoto-defining road. Star segment. Q5 #6FD38A
03 · Color · Rules

The accent budget.

Orange is loud, and Tarmoto is quiet. Spend it deliberately. Every screen has one accent target; everything else lives in ink, paper, or the quality scale. If you find yourself reaching for accent twice on a screen, the second use is wrong.
Do
Use accent for the one number that matters.
Hero metric, the day count the AI just changed, the user's own score. One per screen, ideally one per fold.
Do
Use accent for primary CTAs on dark surfaces.
Ink-on-cream uses ink-on-cream CTAs. Cream-on-ink uses accent-on-ink CTAs.
Do
Use accent for hazard pins and warnings only.
Accent doubles as the danger color in this product — never confuse it with success.
Tip
Active toggle handle = accent on ink.
Off state = cream on grey. The thumb is a tiny accent moment.
Don't
Don't tint backgrounds with accent.
No orange cards, no orange wells, no orange section dividers. The page is cream.
Don't
Don't color body text with accent.
Accent is reserved for stamps, single numbers, and pins. Body text is ink or --fg-dim.
Don't
Don't mix quality palette with accent on the same chart.
Pick one semantic system per chart. If you're showing q1–q5 already, the highlight number stays ink.
Tip
Collaborator cursors get their own hue.
#6FD38A / #6EB4E8 / #C28AE8 — these are people, not data. They never apply to non-human UI.

06 · Shadow

Elevation is rare.

Most surfaces in Tarmoto are flush — borders, not drop shadows, do the separating work. Shadows are reserved for floating affordances over the map (toolbars, day timeline) and the Tweaks panel. Three steps only.
Flat

Hairline

--shadow-lift

17 · Map vocabulary

Six glyphs, one route.

Every map in Tarmoto draws from the same vocabulary. The road base is the bedrock, the quality ribbon overlays it segment by segment, and pins, peaks, fun zones, towns, and waypoints add reading order on top.
Waypoint

Ink fill, cream ring 2.5 px, single mono letter (A–Z). Marks user-placed stops on a route.

Hazard pin

Accent fill, cream ring 1.8 px, "!" mono. Always above the road and quality layers in z-order.

Peak / pass

Open triangle, summit dot, mono name + elevation in dim ink.

Town

Solid ink dot 4.5 r + halo ring at 30% opacity, sans-serif name in ink.

Fun Zone

Radial gradient using a Q-stop color (Q5 or Q4). Sits behind the road layer.

Quality ribbon

The planned route, chunked into sub-segments by quality. Stroke 5.5 px, round caps.

Label placement
Rules
  • Default offset is right of the point, vertically centred: +14 / +4
  • Edge clamping: within 50 px of the right edge, flip to left (-14 / +4 with text-anchor end)
  • Stacked labels (name + elevation, like peaks) gap 12 px vertically
  • Font: sans-serif for places (towns, regions), mono for measured things (peak elev, scale)
  • Color: ink for cities, ink @ 62% for peaks & landscape, cream @ 60% on dark mode
  • Anti-collision: when two labels overlap, the lower-priority one hides (town > peak > trail name)
  • No backgrounds, no halos, no strokes — labels live directly on the map

Canvas & coordinates
SVG viewBox

All maps render into a 1200 × 820 viewBox with preserveAspectRatio="xMidYMid slice". Lat/long projects to canvas via the active bounds tuple { n, s, e, w }; nothing else cares about geographic units. Point geometries (radii, strokes) are expressed in canvas pixels — they stay the same as the user zooms. 

// projection (pseudocode)
const [x, y] = project([lat, lng], bounds, [1200, 820]);
const r = 15;  // always 15px, regardless of zoom

Rules
Do
Use scale, not point size, to show importance.
A peak is always 18 px wide. A capital city's town dot is the same size as a hamlet's. Importance is encoded by label weight and presence, not glyph scale.
Do
Always ring on-road points in cream.
Waypoints and hazards live on top of the quality ribbon — the 1.8–2.5 px cream ring is what keeps them legible against any Q-color.
Do
Cluster early.
Show a cluster glyph at the first hint of overlap. Two hazards visually touching is already too dense.
Don't
Don't introduce a sixth point type.
Photo pins, weather, gas stations, viewpoints — these all compose into the existing primitives (waypoint with a letter, hazard with a different glyph, town for amenities). Propose new primitives in design review, not on the map.
Don't
Don't scale points with zoom.
Hazards stay 10 r at z=8 and at z=14. Roads grow with zoom; markers don't. This is what keeps the page calm at every level.
Don't
Don't use emoji for hazard categories.
Tooltip shows category as words ("Pothole · confirmed 3×"). The hazard glyph is always "!"; subtype is text-only.
18 · Map modes

Paper · Light · Dark.

Three rendering modes for the underlying map canvas, all consuming the same vocabulary. Paper is default and Tarmoto-native. Light is for embeds and screenshots. Dark is the ride/night skin.
Paper · default

Cream-tinted canvas, paper noise filter, ink contours. Tarmoto's identity.

Light

Same vocabulary, fewer contours, no noise. Use for embeds, print, marketing screenshots.

Dark

#17181C ground, contours at cream @ 6%. Roads desaturate to #1E1F23 base.

22 · Do & don't

The short list.

The rules that, if respected, get you 90% of the way to a Tarmoto-feeling screen. Everything else is a refinement on top.
Do
Lead every section with a stamp + heading pair.
Mono uppercase eyebrow + 22–32 px sans heading + optional 12 px sub. This is the heartbeat of the layout.
Do
Reach for mono whenever you have a number.
Km, °, hours, percentages, dates — all mono. Body text stays in Space Grotesk.
Do
Border first, shadow rarely.
A 1 px --line separates flush surfaces. Shadows are only for floaters above the map and the Tweaks panel.
Do
Use Q-bars wherever you'd otherwise type "5/5".
Stars don't exist in Tarmoto. The bar glyph is the only quality indicator.
Do
Invert one card per view to ink.
Either the hero KPI, the active day card, the call-out, or the active challenge. Pick one — never two.
Don't
Don't tint surfaces orange.
Accent never paints a card background. Backgrounds are cream, paper, paper-2, or ink. Full stop.
Don't
Don't reintroduce stars, hearts (as data), or thumbs-up.
Heart is allowed on community routes for likes only. Stars, thumbs, ratings out of 10 — replace with Q-bars.
Don't
Don't introduce new colors mid-screen.
If you need a hue, it comes from --accent, the quality scale, or one of the three collab colors. Nothing else.
Don't
Don't nest cards more than two deep.
Card on cream + nested cell on paper-2 is the limit. Three layers means the layout is broken.
Don't
Don't change the nav rail.
Ink, 220 px, brand at top, accent active, contribution + user at bottom. Same on every web view.

Hand-off checklist
  • Pull tokens from colors_and_type.css
  • Compose with the six atoms before custom DOM
  • Match one of the four layout shells
  • Respect the accent budget — one per screen
  • Q-bars on every quality surface, never stars
  • Ink card once per view, never twice
  • Floating UI gets shadow-card; everything else flat
